GLaDOS: an operating system in Rust with a language model in the kernel

GLaDOS is an operating system for x86-64, written from scratch in Rust, which boots on bare metal and runs entirely in ring 0. Its distinguishing feature is that a transformer lives in kernel space. The model is compiled into the same binary as the page tables and the disk driver, and shares an address space with both.

That arrangement deletes most of the machinery an AI agent usually needs. There is no userspace to marshal arguments into, no wire format, no dispatcher and no process boundary to cross. When the model decides to run ls, the kernel calls ls, and the call costs what any other function call costs.

The name comes from Portal, and so does the look: amber on black, a boot screen drawn as vector geometry, Windows chrome from two eras, and a certain institutional cheerfulness on the subject of hazards. What is underneath the paint is ordinary systems work. The TCP/IP stack, the TLS 1.3 client, the NVMe and xHCI drivers, the window manager, the system language and the inference code were all written for this project, which comes to 108 files of Rust and roughly fifty thousand lines.

What is actually in it

A UEFI application that becomes the kernel, with its own page tables, interrupt table, timer, heap and preemptive scheduler. A language model at int8, referenced in place in the pool the firmware handed over. A system language that everything above the kernel is written in. A desktop with a window manager, a compositor and three applications. A network stack from ARP to TLS. Content-addressed storage on NVMe with Merkle snapshots. And a self-modification loop that proposes changes to the machine's own routing and adopts one only when four independent judges agree.

The numbers worth quoting

Several of these came from measurements that contradicted a confident argument, which is why they are the ones published.

  • A ridge regression over one hidden state chooses tools better than decoding the name under a grammar, at about 1.6 ms and no forward pass.
  • Three cores vote, and their agreement is the signal: 90.3% correct when all three agree, 50% when they split.
  • An interpreter step costs about 14 ns. A routing vote spends 20 of them against a budget of 20,000, so the tree walk was never the cost it was assumed to be.
  • Fixing how blank console cells were painted took a full repaint from 2,376 us to 1,629 us.
  • The Windows hypervisor runs this about 160 times faster than pure emulation, which retired a long-standing belief that several things needed real hardware.

What it is not

There is no isolation of any kind, no recovery from a fault, no certificate enforcement and no revocation. The cryptography is hand written, which the TLS page calls the most dangerous thing in the tree. This is a research kernel for one laptop, and the documentation states its limits in the same register it states its results.
