GLaDOS / Wiki / Ring 0

Ring 0

x86 has offered four privilege levels since the 286, and in practice systems use two of them: ring 0 for the kernel and ring 3 for everything else. Rings 1 and 2 have been decorative for decades, partly because paging distinguishes only supervisor from user and cannot tell the middle two apart. The boundary between 0 and 3 is what makes a program crash while the machine keeps running.

GLaDOS runs entirely in ring 0. There is no ring 3, no syscall instruction, no per-program address space, and no TSS entry for a ring-0 stack to switch to, because there is never anything to switch from.

What the boundary costs

Crossing it is expensive. A syscall saves registers, switches to the kernel stack, validates every pointer that came across because the caller may be lying about them, and reverses all of it on the way back. On systems with kernel page-table isolation it swaps page tables twice and pays the TLB misses that follow. For a call that reads a megabyte off a disk this is rounding error. For a great many very small calls it becomes the dominant cost.

A language model driving an operating system makes a great many very small calls. A tool invocation, a namespace lookup, a read of the applet table, the sampler asking which tokens the grammar still permits. In a conventional design each of those is a boundary crossing, and the grammar question arrives once per token.

Removing the boundary also removes the reason tool calls are text at all. With the model and the applet table in one address space, the sampler is constrained by the real table and returns an index into it. That property falls out of the privilege decision and was never designed separately.

What removing it costs

Precisely the things the boundary was buying, and it is worth being specific:

  • A null dereference is a page fault in the only address space there is. If the handler cannot recover, the machine stops.
  • A buffer overrun can reach the page tables, the interrupt descriptor table, or the model's weights, and the hardware will not object.
  • There is no kill. A runaway loop owns the machine until the timer interrupt preempts it, and if it has disabled interrupts, not even then.
  • A script that exhausts the heap exhausts the only heap, and the allocator has nowhere to fail back to.

Some of that is mitigated. Virtual page zero is deliberately left unmapped, which costs one extra page table for the first 2 MiB and turns a null dereference into a legible fault report. Stored programs run under capabilities, and the sandboxed set refuses raw ports and the network by name before arguments are examined. NVMe writes stay locked until something claims a specific range, and the range is enforced on every write.

None of that is isolation. It is one interpreter in one address space, and it stops accidents while remaining completely open to intent.

A fault that said nothing

With no recovery, the fault report is the entire diagnostic budget, so it is worth checking that it works. It did not. Every fatal handler printed to the framebuffer console first and the serial port second, and painting from inside an interrupt gate raises a general protection fault on this kernel. The first line of every report died in the console before serial was ever reached, and what a person saw was a machine that went quiet.

The report is now emitted twice, whole, to the serial port before the console is touched at all. A fault taken while reporting a fault prints one line and halts rather than recursing, which it previously did as an unbroken column of identical exceptions. The console fault itself is still there and is now visible instead of silent.

Why that is a defensible trade here

Because the threat model is small and stated. This is a research kernel for one laptop, booted from a USB stick, running a model that is not adversarial and is in any case too small to be much of anything. The failure being designed against is a bug, and the instrument against bugs is the self-test output at boot.

Claiming a security boundary and enforcing it incompletely would be worse than having none, because it invites the system to be used as though the boundary were real. So the documentation says there is no isolation, the shell says it, and the TLS page says the equivalent thing about certificate validation.
