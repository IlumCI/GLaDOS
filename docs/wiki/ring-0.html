GLaDOS / Wiki / Ring 0

Ring 0

x86 defines four privilege levels. In practice systems use two: ring 0 for the kernel, ring 3 for everything else. The boundary between them is what makes a process crash instead of a machine crash.

GLaDOS runs entirely in ring 0. There is no ring 3, no syscall instruction, and no separate address space per program.

What the boundary costs

Crossing it is not free. A syscall saves registers, switches stacks, changes page tables on kernel-page-table-isolation systems, validates every pointer coming across, and reverses all of it on the way back. For a call that does real work this is noise. For millions of tiny calls it is the dominant cost.

An in-kernel language model makes millions of tiny calls. A tool invocation, a namespace read, a tensor operation dispatched by the router, all of it would cross the boundary in a conventional design.

What removing it costs

Everything the boundary was buying:

  • A null dereference is a triple fault and a reboot, not a segfault.
  • A buffer overrun can overwrite the page tables.
  • There is no kill, a runaway loop owns the machine.
  • A script that exhausts the heap exhausts the heap.

The system says this plainly rather than claiming a security model it does not have. Capabilities exist for scripts, a tame mode that refuses raw port access by name before arguments are even examined. But this is one interpreter in one address space with no isolation. It stops incompetence, not intent.

Why that is acceptable here

Because the threat model is honest: this is a research kernel for one laptop, running one model that is not hostile, it is small. A system that claimed isolation it could not enforce would be worse than one that says there is none.
