Testing an OS with no test runner

There is no cargo test. This is a no_std UEFI binary with no host test runner, so the test suite had to be somewhere else. It is in three places.

1. Self-tests at boot

At every boot the system exercises the heap, timer, clock, namespace, 13 sets of published cryptographic vectors, constrained decoding and the linear probe, printing ok or FAIL per line. That output is the test suite.

It is easy to scroll past, and it does catch real bugs. An ECDSA break was visible in the crypto block for an entire debugging cycle while the output was being sliced away to look at something else.

2. A scripted QEMU harness

A driver script boots QEMU, stages the binary, resets the firmware's NVRAM to a pristine state, and drives the shell over a serial socket, sending commands and capturing everything.

Two details that were not obvious. QEMU's Windows stdio backend reads console handles directly, so piping a script into it does nothing at all . Silently; a TCP socket behaves like a socket everywhere. And a stale firmware boot entry sends the machine to the UEFI shell, which looks exactly like the system failing to boot, so the NVRAM is reset every run.

The harness also captures the framebuffer through QEMU's monitor and converts it to PNG, because a serial log says nothing about whether the screen is right.

3. A numeric oracle

For the model, a NumPy reference implementation reads the converted checkpoint and produces logits to diff against. Reading the converted file rather than the original is the point: a converter bug shows up in both, so only a genuine kernel bug appears as a mismatch.

This is what caught the RoPE convention, which no amount of reading the code would have. Both conventions are perfectly reasonable code.

The habit underneath

Measure, do not assume; and look at it. Repeatedly in this project a confident belief turned out to be false, and a cheap deterministic test found it: the oracle found the RoPE bug, screenshots found three layout bugs the serial log could not, and an A/B against a deliberately tiny context isolated an off-by-one to a single token.
