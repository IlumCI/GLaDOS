Tokenizers

A tokenizer that is subtly wrong produces text that still looks like text. That single property is why this component gets more verification than most of the ones around it.

The regexes differ, and it matters

Byte pair encoding is a merge table applied greedily, and it is the easy half. Before any merging happens, the input is split into pieces by a regular expression, and that pattern is part of the trained model rather than an implementation detail.

SmolLM2 uses the GPT-2 pattern. Qwen3 spells out the cl100k one, where a word may be led by any non-alphanumeric character so that an opening bracket and the word after it form one piece, digits arrive one at a time, and punctuation swallows the newlines that follow it.

Merging is identical in both cases. The pieces the merges are applied to are not.

Twelve percent of nothing visible

Using the GPT-2 pattern on a Qwen3 checkpoint moved about twelve percent of tokens across the training corpus here. There was no error, no exception and no warning. The model was simply being fed sequences of a kind it never saw in training, and it responded by being slightly worse in a way that reads as the model being small.

Every checkpoint therefore carries which pattern it was trained with, and the kernel reads it from the file rather than guessing from a name.

Verify against the reference, always

The conversion tool has a verification mode which reimplements the kernel's algorithm in Python and compares it against the reference tokenizers library over a corpus. It is not optional, and the reason is the first sentence of this page.

The boot self-tests carry a set of cases for both patterns, checked against the reference output, so a regression in the kernel's implementation shows up in the same place everything else does.

What the kernel implementation does

It reads a compact binary vocabulary with the merge ranks, applies the pattern the header names, and merges greedily by rank. Special tokens are matched before the pattern runs so a marker is never split. The longest single token in this vocabulary is 81 bytes, which matters only because a fixed buffer somewhere has to be at least that.

An earlier design tried to derive the pattern from the vocabulary's contents. It worked on two checkpoints and would have failed silently on the third, which is the same failure this whole page is about, so it was replaced by recording the answer explicitly at conversion time.
