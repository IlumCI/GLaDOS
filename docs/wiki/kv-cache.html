GLaDOS / Wiki / The int8 KV cache

The int8 KV cache

Every token attends to every token before it, so the keys and values of the whole conversation have to be kept. That store grows linearly with position and is the reason a small model can still be expensive to talk to.

The arithmetic

The cache is layers times positions times key-value heads times head width, twice over for keys and values. For this checkpoint at 512 positions that is 112 MiB, which is a large fraction of the kernel heap and is why the context window is chosen at conversion time and printed when it is chosen.

Storing it at int8 with per-row scales costs a quarter of the floating point equivalent. The quantisation error lands on attention scores that are about to go through a softmax, which is tolerant of small perturbations in a way that is easy to verify by generating text and reading it.

An asymmetry worth knowing

Quantising the cache makes the loss piecewise constant in anything upstream of a cached key or value. Differencing a layer-zero query through the quantised forward pass reported a gradient of -0.305 where the analytic value was of order 1e-6, because the quantisation step swallowed the perturbation entirely.

So training keeps an exact floating point cache and serving keeps the quantised one. That is a switch rather than a second implementation, for the same reason the tape is not a second forward pass: two implementations that are supposed to agree do not stay agreeing, and the one that drifts is the one nobody notices. Training against those gradients is a straight-through estimate, which is the usual bargain and is written down where it is made.

Attention sinks and a sliding window

Within 64 positions of the trained length, the cache becomes a ring with a small number of pinned entries at the front and evicts its oldest turns instead of stopping. The measured behaviour is a 511-slot ring keeping 468 positions, then continuing past position 649.

That works because of a coincidence worth stating. Unwindowed, a position lives at the slot with its own number; windowed, it lives at a wrapped offset past the sinks. Those are the same address until the ring would first wrap, so switching before that moment needs no entry re-seated. Switching at any other time genuinely cannot be re-seated, and the code clears the cache instead of pretending.

The first version of this got it wrong in the loudest available way and the output still looked fine. It cleared unconditionally, so a feature announcing that it forgets its oldest turns forgot all of them, position fell from 468 to 72, and the model carried on answering fluently. Only the cache inspector showed it.

The system turn is pinned

The same mechanism does something more useful. A pinned slot never recycles, so setting the sink count to the token length of the system turn pins the instructions, the applet list and the operator's notes for as long as the conversation runs, in their original slots and at their original angles.

That count is taken by encoding the system turn exactly the way generation will, rather than estimated, because a count that ran short would pin part of a turn and let the rest scroll away. It is clamped to a third of the trained length, and the cache inspector prints span and pinned separately so a clamp shows up as the two figures disagreeing.
