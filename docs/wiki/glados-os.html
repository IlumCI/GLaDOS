GLaDOS OS

GLaDOS OS explained: a from-scratch Rust kernel for x86-64 with a transformer running in ring 0, no syscalls, and one address space.

GLaDOS is a single-address-space operating system whose distinguishing feature is that a transformer runs inside the kernel. There is no userspace to put it in — there is no userspace at all.

The structural choice

Conventional systems separate kernel and user code with a privilege boundary, crossed by syscalls. That boundary buys isolation and costs a context switch. GLaDOS removes it entirely: everything runs at ring 0, in one address space, with no syscalls and no memory protection between components.

The consequence that matters is what a tool call becomes. In a normal AI agent, the model emits text, something parses it, a dispatcher looks up a handler, and the call crosses a process boundary. Here the model names a function under a grammar built from the live function table and the kernel calls it. There is nothing in between.

What this costs is equally plain: a bug anywhere can corrupt anything. There is no adversary model, and the system does not pretend to have one. It stops incompetence, not intent.

Boot

There is no bootloader. UEFI already delivers long mode, ring 0 and an identity map, so the UEFI application is the kernel — no ELF loading, no relocation, no handoff ABI. See UEFI as the kernel.

The model, tokenizer and root certificates are read before ExitBootServices, because that is the only moment a filesystem exists. After that the system is on its own page tables with no firmware services at all.

Subsystems

  • Inference — a transformer with no allocator behind it and no libm to call.
  • Networking — ARP through TCP, DHCP, DNS and TLS 1.3, all hand-written.
  • Storage — NVMe under a content-addressed object store where a snapshot is one hash.
  • USB — xHCI rings, enumeration, and a CDC Ethernet driver that carries real traffic.
  • Graphics — a Windows 3.1 desktop drawn pixel by pixel into a GOP framebuffer.

The interesting negative results

Training an adapter head on top of the model hurts at this data scale. A Product-of-Experts council of three classifiers does not beat the single best one. Both stay in the source tree, because the reason to know them is the reason they were worth measuring.
