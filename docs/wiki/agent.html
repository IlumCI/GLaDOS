GLaDOS / Wiki / The agent loop

The agent loop

Typing agent list the files in /sys queues an episode. The shell keeps its prompt and a step budget counts down. Each step follows the same shape: the model reads the goal, the transcript so far and the applets it may call; something decides which applet fits; the kernel dispatches it as an ordinary function call; whatever the applet prints becomes the next step's observation. When the model judges the goal met it names done, and the episode lands as a transcript under /ai/episodes.

Trust works the way it does everywhere else in the system. At read-only trust the mutating applets are absent from the grammar entirely, so no decision sequence can reach them; at full trust everything is reachable. Enforcement lives in the sampler, ahead of any choice.

Three tiers, spent in order

A step does not always need the transformer. The cheapest tier answers first and the expensive ones run only when confidence is missing:

  • Reflex. The ridge router scores every applet from one hidden state and the two counting cores corroborate it. Where all three name the same applet they measure 90% right, so that answer dispatches immediately and no token is generated.
  • Pulse. One greedy walk under the grammar at temperature zero: a single pass over a handful of tokens, handling everything the reflex has no opinion about.
  • Deliberation. The engine state is captured, cache included; candidates are then sampled at temperature and ranked by the router's scores. The winning candidate's keys stay in the cache, which is exactly the context wanted for decoding that applet's arguments.

Forks are budgeted by the caller because each one copies the KV cache, the largest allocation in the system. The ladder exists so that copy is only ever paid for when the cheap tiers had nothing confident to say.

Skills

A successful episode can be frozen into a skill with agent learn <name>: the transcript's decisions become a program under /ai/tools, and run replays it whenever a matching request arrives. Skills are ordinary programs in the kernel's little language, and their trust level comes from what they call: a script invoking write makes every grammar admitting that script a full-trust grammar.

One builtin makes this composition useful. applet("ls /sys") calls the OS from inside a program and returns the captured output as a string. Captures nest, because a skill may call an applet that itself runs a skill, so the capture is a stack and each call collects into its own frame.

Prefill made episodes affordable

Every step rebuilds its context, and feeding a prompt token by token reads every weight once per token. The prefill pass now walks the prompt in 64-row chunks through which each weight matrix streams once, with per-element arithmetic unchanged, so results match single-token feeding bit for bit. Under full emulation an episode step fell from more than half an hour to about two minutes.

The same change tightened a subtlety worth stating: the position marker now travels with the cache through every path, including fork capture and restore, so a resumed walk always continues exactly the context it started from.

The transcript is the interface. Everything above is readable: cat /ai/episodes/0001.txt shows the goal, the tier each choice came from, the applet calls and their observations. The desktop's agentlog window tails the same stream.
