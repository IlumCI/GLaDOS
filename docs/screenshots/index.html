GLaDOS OS screenshots

Captured from the running system under QEMU, through the emulator's monitor rather than a camera pointed at a screen. These are the framebuffer's actual contents.

Desktop with terminal and Program Manager. The desktop as it comes up: the terminal showing its own boot log, Program Manager, and a taskbar. Every pixel is drawn by the kernel into a UEFI framebuffer. There is no graphics library under it.
Desktop wallpaper. With the terminal minimised. The wallpaper mark is drawn as geometry at boot rather than decoded from an image. There is no image decoder in the kernel.
The model answering. The resident model answering what is an operating system from inside the kernel. No process, no API, no server.

What you are looking at

The window chrome is genuine Windows 3.1 construction: a #C0C0C0 face, two-pixel bevels light on the top-left and dark on the bottom-right, title bars that fill with the selection colour when focused. Over that sits the Aperture palette.

There is no graphics library beneath any of it. The kernel gets a base address, a width, a height and a stride from UEFI's Graphics Output Protocol, and everything above that. Glyphs, bevels, the window manager, the wallpaper. Is written by hand. See the GUI page for how, and for the bug that only a screenshot could have found.
