GLaDOS / Screenshots

GLaDOS OS screenshots

Taken from the running system under QEMU, through the emulator's monitor, so each one is the framebuffer's exact contents. The first four are from 1.4.3; the rest are older and say which release they are.

The desktop as it is now. 1.4.1 replaced the renderer: a compositor that repaints only what changed, anti-aliased shapes, OKLab gradients that do not band, glass captions over a blurred copy of the wallpaper, shadows, windows that tile and animate, and text set in Noto Sans and Cascadia Code. The wallpaper is still computed rather than decoded -- the sun, the hills and the rim light are drawn at boot from arcs and ramps. The terminal is showing perf, which reports the clock, the governor, and how fast memory and the screen can be written.
The wallpaper follows a nervous system. Beside the model runs the adult fruit fly from the FlyWire connectome, 138,639 neurons simulated spike for spike and fed the machine's own events as senses: keys are touch, a fault is pain, a hot CPU is heat. Its mood is on the wall. Content, the room becomes a white test chamber; calm, it is the sun as designed; upset, the scene drains to grey and is scored with scanlines; asleep, the sun is eclipsed. The same mood changes the model's manner and wears down the mask on its voice. Nothing it reads decides what the machine is allowed to do.
Watching it. The Oracle's Brain tab, here on the compiled-in worm (295 neurons) under a noxious input: what it senses, what it is driven to do, its dopamine, octopamine and serotonin, and how it feels and why -- valence -855, agitated. brain poke pain at the shell does the same, and the wallpaper above answers it.
A graphics card, from ring 3. linux bg starts a 32-bit OpenGL program as a background job, and the shell stays yours. The program is ordinary: unmodified Mesa does Vulkan on the host's RTX 3050 through a render node this kernel serves, Zink puts OpenGL 4.6 on top, and the window it draws in belongs to Skywalker, the Wayland server inside the kernel. Nothing in the kernel knows what Vulkan is. This path runs in a virtual machine with the host's GPU behind it; a native driver for the laptop's own GPU is the next step.
From 1.3.5. The machine writing an application. author clock show the time of day queues a run and hands the prompt straight back, which is the point of it: the shell stays yours while it works, and agent stop cancels. The Writing window is the run reporting on itself -- which step of its budget it is on, how many of the clauses it set itself have been met, and the last check verbatim. There is no progress bar, because a step can be a skeleton that lands instantly or a decode that takes seconds, and the loop ends when the checks pass rather than after a known amount of work. It leaves a draft and adopts nothing: app try runs it, app take keeps it. Nothing here calls out to anything. The model that decided to write this is in the same address space as the code drawing the window it is reporting into.
From 1.3.5. An unmodified Linux binary, at ring 3. This busybox came from busybox.net and nothing here touched it. The kernel loads it, reports the segment it placed and where the entry landed, and then busybox answers uname -a for itself. Underneath is every syscall it made, with the arguments it passed and what it got back: seven of them, ending in exit_group. The same binary run as sha256sum hashes its own file to the digest the development machine computes over the same bytes, which is the check that settles this path against an implementation nobody here wrote.
From 1.3.5. An SDL2 program, on a machine with no display server. Not much to look at, which is most of the point. The program is ordinary SDL2 and knows nothing about this machine; SDL reports video driver: glados, a display of 1280x800 and a surface with a pitch of 5120 bytes. The diagonal is why the picture is shaped like this. Eight flat bars come out looking perfectly correct under a wrong stride, as long as the stride is a multiple of the bar width, and a line from corner to corner cannot. It runs straight.
From 1.3.5. The Oracle. TempleOS had God Says, which drew words from a list seeded by the timing of the operator's own hands. The entropy here is the same, taken from every keyboard and mouse interrupt, and the subject is changed to the one future this machine can honestly claim to know, which is its own. It records heap, task switches, touch rate and task count once a second, which are the four tabs along the top, fits a small linear system to them with the same Cholesky solver the router uses, and rolls the state forward under three interventions: left alone, carried on, put under load. Solid up to the now line is what happened. The coloured forks after it are what the fitted model expects, here three futures from 37 samples. It is a controlled linear system fitted from real telemetry, so it is a projection and never a prophecy. The first draft had the machine hallucinate words the way TempleOS did, and was scrapped for exactly that reason.

What you are looking at

There is no graphics library beneath the desktop. UEFI's Graphics Output Protocol hands the kernel a base address, a width, a height and a stride, and everything above those four numbers is this project's: the shapes, the gradients, the glass, the window manager and the compositor. The two typefaces are outlined by fontdue, the one outside crate the kernel admits, and only for fonts.

A frame is a diff of two scenes. The desktop lists what is on screen as layers, each with a fingerprint of exactly what its painter reads, and the layers that changed since the last frame are the damage -- at most sixteen rectangles, repainted and written out. An idle desktop writes about a dozen rows ten times a second, which is the clock. render verify on composes a full reference frame after every incremental one and names the first pixel that disagrees.

None of these were arranged by hand. The desktop is driven over a serial line: a script sends shell commands, and the emulator's monitor is asked for the framebuffer. Anything the pointer can do a keystroke can also do, which is a constraint the testing imposed and the interface kept.
