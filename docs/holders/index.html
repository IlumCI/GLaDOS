GLaDOS / Token / Holder chats

Holder chats

Holders of at least 2% of the $GLADOS supply are let into the holder chat on Telegram, and holders of 4% into the inner one as well. You prove the holding by signing a message with any wallet that holds it; the share is read from the token contract on Robinhood Chain, by the server, against totalSupply() at the same block.

Start in Telegram: send /verify to the holders bot. It answers with a link to this page that names your Telegram account and works once.

Nothing on this page will ever ask for a seed phrase, a private key, a transaction or a token approval. It asks for one signature over a message you can read in full first. If any page claiming to be this one asks for more, it is not this one. Close it. The bot never messages you first.

Which wallets work

Any wallet that can sign a message. Four routes, and the page offers whichever apply:

  • A browser extension -- MetaMask, Rabby, Phantom, Coinbase Wallet, OKX, Brave and the rest. Each installed one announces itself through EIP-6963 and is listed by name, so with two installed you choose which signs rather than whichever loaded last.
  • A wallet app on your phone -- open this page inside the app's own browser, where it is an extension like any other; or use WalletConnect, which shows a QR code for a wallet on another device and deep-links to one on this device. It is the one route that loads somebody else's code: choosing it fetches the WalletConnect library and contacts Reown's servers, including their analytics endpoint. Nothing is loaded from anywhere but this site and its server until you choose it.
  • A contract wallet -- Safe, Coinbase Smart Wallet, passkey and other ERC-4337 accounts. There is no key to recover from their signatures, so the server asks the account itself through EIP-1271, on Robinhood Chain. The account must be deployed there; an ERC-6492 signature from one that is not yet deployed is refused, because checking it means running a factory this server has never read.
  • Anything else -- a hardware wallet, a command line, a wallet with no browser at all. Choose Sign by hand: copy the message, sign it with your wallet's own sign message feature (for example cast wallet sign --ledger "$(cat message.txt)"), and paste the signature back.

Your wallet does not need Robinhood Chain added. A signed message proves which key or account produced it and says nothing about a chain. The balance is a separate read the server makes.

What this does, exactly

  1. The bot creates a single-use session for your Telegram account and sends you a link carrying it. Only its hash is stored.
  2. This page asks the server for a nonce and an EIP-4361 message naming this domain, the chain, an expiry and your Telegram user id, and shows it to you in full.
  3. Your wallet signs it with personal_sign, which is prefixed so that a signed message can never also be a valid transaction.
  4. The server checks the signature, spends the nonce, reads every wallet you have linked and the total supply at one block, and decides the tier on their sum. The bot then sends you a join request link for each chat you qualify for.
  5. When you use that link the bot reads the chain again before approving, and a scheduled recheck removes anybody whose holding has fallen below the bar.

Because the message names your Telegram account, a signature made for one account cannot admit another. A wallet can belong to one Telegram account at a time, so one holding cannot be lent to a whole chat. Up to five wallets can be linked to one account and are measured on their sum.
